Overview

Kaizen is a continuous improvement method: small, focused projects that fix one measured loss at a time.

This module records each improvement as a project tied to a loss you can measure:

  • the baseline loss per month before the fix, with its date;
  • the 5 Why analysis (up to five lines, one marked as the root cause);
  • the Ishikawa causes, grouped in the six categories Man, Machine, Method, Material, Measurement and Environment;
  • the corrective actions, each with a responsible person and a deadline, and an overdue flag;
  • the loss per month measured after the fix, and the savings against the baseline, including an annual projection.

A project can be closed only by a Kaizen manager, from the Verification state, when a root cause is recorded, every action is done, the baseline is positive and the loss after the fix has been measured.

Usage

Kaizen projects follow a fixed flow: Draft → Analysis → Actions → Verification → Done.

  1. Go to Kaizen → Projects. The list opens on the Open filter, with the loss type, responsible, deadline, baseline loss, current loss, monthly savings and state of each project.
1 Kaizen Projects list with the Open filter: two projects in the Actions state, with baseline loss, current loss and monthly savings
  1. Click New, enter the project name, Loss Type, Responsible, Start Date and Deadline. On save the project gets a KZN/ reference. In the Baseline and Results tab, enter the Baseline Date and the Baseline Loss / Month, and optionally the Target Loss / Month. Savings stay at zero until a measurement after the fix is recorded. Click Start analysis.
2 Project in Draft: Baseline and Results tab with the baseline loss of 12,000.00 per month, the target and savings still at zero
  1. In the 5 Why tab, add up to five lines, each answering "why?" for the line above, and tick Root Cause on the line where the analysis stops. Only one line can be the root cause.
3 5 Why tab: five lines, the last one about the missing preventive maintenance plan is marked as root cause
  1. In the Ishikawa tab, add the possible causes, each with a Category (Man, Machine, Method, Material, Measurement, Environment). Click Start actions.
4 Ishikawa tab: one cause in each of the six categories
  1. In the Actions tab, add each corrective action with a Responsible and a Deadline. Click the Done button on the line when the action is finished: Done On gets today's date. Overdue open actions are shown in red, finished ones in green.
5 Actions tab: a finished action in green, an overdue one in red and one within its deadline
  1. When every action is done, click Start verification. Enter the Measured Date and the Current Loss / Month measured after the fix. Monthly Savings is the baseline loss minus the current loss, Annual Savings (projection) is the monthly savings × 12, and Target Reached is ticked when a target is set and the measured current loss is at or below it.
6 Project in Verification: current loss 3,500.00, monthly savings 8,500.00, annual projection 102,000.00 and Target Reached ticked
  1. A Kaizen manager clicks Close project. Closing is refused without a root cause, with open actions, with a zero baseline or without a measured date. The state becomes Done and Closed On is set. Cancel, also manager-only, stops a project in any state except Done.
7 Closed project in the Done state, with the Closed On date
  1. Kaizen → Ishikawa lists the causes of all projects, grouped by category.
8 Ishikawa Causes list grouped by category, with the project and the cause on each line
  1. Kaizen → Actions lists the actions of all projects, with overdue ones in red: the follow-up list for the weekly improvement meeting.
9 Kaizen Actions list: the actions of both projects, the overdue one in red
