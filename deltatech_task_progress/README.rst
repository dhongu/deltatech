Technical module: runs a long task step by step in a progress dialog,
several steps at a time, instead of a single request that times out or
blocks the screen.

A model inherits ``task.progress.mixin`` and returns
``_task_progress_action(...)`` from a button. The dialog calls the step
method once per item (a page of a PDF, a batch of records), a few in
parallel, each in its own request and transaction, and shows:

- the progress bar, the items done and an estimate of the time left;
- the counter returned by the steps (lines read, records created);
- the items that failed, with their errors, and a button to run them
  again;
- a button to stop after the items in progress.

When every item is done, the dialog calls the finish method and opens
the action it returns (a preview, the created records). Closing is
blocked while items are running.

Used by: ``deltatech_ai_purchase_pdf`` (vendor invoice PDF read with AI
page by page).

Usage
=====

In the consumer model:

.. code:: python

   class MyWizard(models.TransientModel):
       _name = "my.wizard"
       _inherit = ["task.progress.mixin"]

       def action_run(self):
           return self._task_progress_action(
               "run_part",
               items=[0, 1, 2],
               finish="action_done",
               parallel=3,
               title=self.env._("Reading the document"),
               unit_label=self.env._("parts"),
               count_label=self.env._("lines"),
           )

       def run_part(self, index):
           # one item, one transaction: write the result on a row of its own
           ...
           return 12  # added to the counter

       def action_done(self):
           return {"type": "ir.actions.act_window", "res_model": self._name, "res_id": self.id}

Steps running at the same time must not write on the same row (the
wizard included), otherwise they fail with serialization errors: keep
each item's result on a row of its own and merge them in the finish
method. A ``parallel`` higher than the number of HTTP workers of the
server only queues the requests.
