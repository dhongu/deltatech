The standard manufacturing order shows the cost of components only as a
total. This module splits the value of the consumed components into cost
categories (raw materials, semi-products, packing material) and adds a
production cost analysis that compares the consumed value with the
produced quantity.

**Cost category on product categories.** A **Cost Category** field on
the product category form classifies the products of that category as
*Raw materials*, *Semi-products* or *Packing Material*.

**Costs tab on the manufacturing order.** A **Costs** tab on the
manufacturing order lists the value of the consumed components grouped
by cost category. Only component moves that are done are counted. The
**Update** button refreshes the list.

**Production Cost Analysis.** The *Manufacturing > Reporting >
Production Cost Analysis* report (pivot, list and graph) shows, per
manufacturing order:

- the planned quantity and its value at the product cost (*Qty Plan*,
  *Val Plan*), and the produced quantity and value (*Qty Efective*, *Val
  Efective*);
- the consumed value, in total and split by cost category (*Val
  Consumed*, *Val Consumed Raw*, *Val Consumed Packing*, *Val Consumed
  Semifinish*);
- the production value, equal to the consumed value plus 20% for
  indirect costs (*Value production*), and the resulting unit cost
  (*Actually Price*) next to the product cost (*Price Standard*);
- the state and the readiness of the order.

Filters for current, in-production, done, waiting-goods and
ready-to-produce orders, and groupings by category, product, order,
state, company and month, are available. The report opens on done orders
of the previous month.

Configuration
-------------

Set the **Cost Category** on the product categories of your components
in *Inventory > Configuration > Products > Categories*. Components whose
category has no cost category are included in the total consumed value
but in none of the split columns.

Limitations
-----------

- The 20% indirect cost rate used for *Value production* and *Actually
  Price* is fixed in the report and cannot be configured.

Changelog
=========

19.0.1.0.10 (2026-11-03)
------------------------

- Description, summary and banner rewritten from the code: removed the
  BoM overhead field, the rounding at BoM explosion, the changes to the
  manufacturing order confirmation and the automatic lot generation,
  which the module no longer has; documented the cost categories, the
  *Costs* tab and the *Production Cost Analysis* report, with the fixed
  20% indirect cost rate as a limitation.

19.0.1.0.9 (2026-10-17)
-----------------------

- Fixed MRP-002: in *Production Cost Analysis*, the planned quantity of
  a manufacturing order whose unit differs from the product unit (for
  example 2 dozen of a product measured in units) was divided by the
  order unit factor instead of being converted, so the report showed
  0.17 units instead of 24. The planned quantity and the planned value
  now use the quantity converted to the product unit.
- Fixed MRP-004: the *Production Cost Analysis* states and filters still
  used values from older versions (*In Production*, *Ready to Produce*,
  *Picking Exception*), so ongoing orders could not be filtered. The
  report now uses the Odoo 19 states (Draft, Confirmed, In Progress, To
  Close, Done, Cancelled) and adds the *MO Readiness* column; *Ready to
  Produce* and *Waiting Goods* filter on component readiness, *In
  Production* on orders in progress.

19.0.1.0.8 (2026-10-16)
-----------------------

- Development status raised from Beta to Production/Stable: the module
  has been in production use at customers for a long time.

19.0.1.0.7 (2026-10-08)
-----------------------

- Fixed MRP-001: in *Production Cost Analysis*, a manufacturing order
  that consumed products from several cost categories (raw materials,
  packing, semi-finished) had its planned and produced quantities and
  its finished value multiplied by the number of categories. The
  consumption is now summed per order before joining. Finished moves
  with different procurement methods no longer duplicate the order
  either.

19.0.1.0.6 (2026-10-03)
-----------------------

- MRP-003 (security): the *Cost Detail* SQL view
  (``deltatech.cost.detail``) had no company field and no record rule,
  and every internal user could read it, so production cost amounts of
  all companies could be read directly. The view now exposes the
  manufacturing order company (``company_id``) with a multi-company
  rule, and read access is limited to Manufacturing users and Inventory
  users (the groups that can read manufacturing orders). Plain internal
  users without these groups no longer have access to the model.
- Declared the missing ``stock_account`` dependency: the *Cost Detail*
  view sums ``stock_move.value``, a column added by ``stock_account``,
  so a standalone install failed with
  ``column sm.value does not exist``. No change on existing databases,
  where ``stock_account`` is already auto-installed with ``stock`` and
  ``account``.

19.0.1.0.5 (2026-09-29)
-----------------------

- Own module icon, instead of the generic gears it had.
