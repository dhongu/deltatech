Overview

Product Codification

This module enhances Odoo's product management by providing advanced tools for automated internal reference generation, barcode management, and data consistency. It is designed for businesses that require strict and structured product codification across their entire catalog.

Key Features

  • Automated internal reference generation based on predefined sequences.
  • Improved barcode management for product identification.
  • GTIN-13 allocation from the GS1 company prefix: each new product receives the next free code in the range assigned by GS1, with the check digit computed automatically.
  • Consistency checks to prevent duplicate product codes.
  • Supports both products and product variants.

Usage

  • Navigate to Inventory > Products > Products.
  • Create a new product or edit an existing one.
  • The system will assist in generating or validating the product reference (Internal Reference) according to company rules.
Usage

Setup

  1. Create a sequence for the product codes (prefix, for example ZZ, and the number of digits) in Settings → Technical → Sequences (developer mode), or directly from the Code Sequence field of the category with Create and Edit.
  2. Go to Inventory → Configuration → Product Categories and open the category. In the Products group choose the Code Sequence. For barcodes, tick Generate Barcode and choose the Barcode Source: Internal prefix (a 2-digit prefix between 20 and 29, plus the digits of the reference or a random number) or GS1 company prefix (the next free GTIN-13 in the range of your GS1 prefix; fill in GS1 Company Prefix, 6-11 digits; Free GTIN Codes shows how many are left). Barcode Random is ticked by default: with it ticked the internal barcode is a random number; unticked, it is built from the digits of the reference.
1 Product category form, Products group: Code Sequence filled in, Generate Barcode ticked, Barcode Source set to Internal prefix, Prefix Barcode 20 and Barcode Random unticked

Create a product

  1. Go to Inventory → Products → Products and click New.
  2. Enter the name and choose the category configured above. Leave Reference and Barcode empty.
2 New product form, General Information tab: Category set to Piese de schimb, Reference and Barcode fields empty and highlighted
  1. Save the product. The reference is taken from the category sequence and, if the category asks for it, the barcode is generated (from the reference digits if Barcode Random is unticked). A reference typed by hand is kept and no barcode is generated in that case.
3 Saved product: the breadcrumb shows [ZZ0001] Filtru de aer, Reference is ZZ0001 and Barcode is 2000000000015, both filled in automatically

When you create a product from a sales order line with Create and edit, choose the category in the dialog and leave the reference empty: the product gets its code on save. A quick create (name only) has no category, so no code is generated.

Existing products

Open the product (or select several in the list), open the Actions menu (gear icon) and choose Force new internal code to get a new number from the sequence, even if the product already has a reference. Find Duplicate lists, from the whole catalog, the products that share their reference with another product (same active status and company), whatever product you ran it from (products without a reference are listed too, if there are at least two). The existing barcode is not changed.

4 Actions menu open on product ZZ0001 Filtru de aer, with Find Duplicate and Force new internal code at the end of the list

Two active products of the same company cannot share a reference: saving is refused with "Internal Reference already exists".

Versions

19.0.1.2.2 (2026-11-12)

  • Fix: an empty-string Internal Reference (from imports or API calls) is now treated like an empty one, so the code is generated from the category sequence instead of leaving the reference empty and giving a random barcode.
  • Consultant sheet (readme/FISA_CONSULTANT.md), usage guide with screenshots and Romanian translation of the "Prefix Barcode" and "Products" labels on the category form.

19.0.1.2.1 (2026-10-14)

  • The Python uniqueness check of the internal reference honours the "Allow duplicate product codes" group of deltatech_product_unique_code when that module is installed: users in the group can again save duplicate codes.

19.0.1.2.0 (2026-10-14)

  • Internal reference uniqueness checked in Python on product templates and variants, instead of the SQL constraint unique(default_code, active, company_id), which let duplicates through when the product is shared (no company: in PostgreSQL NULL != NULL) and between a shared product and a company product. Variants are now checked too: the internal reference is written there. One indexed query per batch, so imports stay fast; only active products conflict, also when the context comes with active_test=False (marketplace imports). Ported from 18.0.

19.0.1.1.1 (2026-10-09)

  • Apps Store banner (banner.json).

19.0.1.1.0 (2026-10-07)

  • Barcodes from the GS1 company prefix: on the product category, "Barcode Source" = "GS1 company prefix" allocates to each new product the next free GTIN-13 in the range of the prefix received from GS1 (prefix + item reference + check digit). Product and packaging barcodes, including archived ones, are taken into account; the category shows how many codes are still free, and an error is raised when the range is used up.
  • The default internal barcode prefix of new categories is now 20 (GS1 range for internal use) instead of 40, which belongs to GS1 Germany. Existing categories keep their prefix.

19.0.1.0.8 (2026-10-02)

  • Fix the "Find Duplicate" action on product variants: it referenced a non-existent action (product.product_open_variants) and the SQL looked for company_id in product_product (the company is read from the template). Queries moved to SQL() and the models are flushed before the search; regression test added.

19.0.1.0.7

  • Own module icon, instead of the generic gears it had.

Changelog

19.0.1.0.6 (2026-09-25)

  • Fix: the category sequence could propose an internal reference that was already used. Its counter does not know about codes created outside the sequence (catalog imports, supplier invoice imports, mass renumbering, manually typed codes), so "New internal code" and automatic coding on product creation failed with "Internal Reference already exists". When the proposed code is taken (including by archived products or other companies), the sequence is now moved past the highest number already used with its prefix/suffix and the next number is taken. Sequences with date ranges are not synchronised. Ported from a customer project.
