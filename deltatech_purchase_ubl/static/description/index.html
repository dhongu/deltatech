Overview

This module imports vendor invoices in UBL XML format and uses them to update purchase workflows in Odoo.

Key features:

  • Automatic vendor and order resolution
    the wizard keeps the selected purchase order on itself and can also identify the vendor and purchase order from the XML (OrderReference, supplier VAT, supplier name) when context is no longer available.
  • Automatic matching
    products are matched by barcode (GS1/EAN), supplier code, internal reference, or exact name.
  • Purchase order integration
    • existing matching lines are updated (quantity, price, discount) and lines whose product is not yet on the order are added, instead of being silently dropped;
    • the wizard warns before import when the order already has lines, so the user can review what will change;
    • when no purchase order is resolved, the wizard can still identify the vendor from XML and update supplier prices.
  • Price management
    updates vendor prices in product.supplierinfo directly from the XML data.
  • Discount support
    extracts line discounts from AllowanceCharge (ChargeIndicator=false) and applies them as percentage discounts on purchase order lines.
  • Total check
    compares the purchase order total with the XML total (PayableAmount / TaxInclusiveAmount, with untaxed fallback) and shows a warning when there is a difference.
  • Stock automation
    optionally validates the associated stock receipt by matching quantities from the XML.
  • Accounting
    optionally creates and links a vendor bill from the purchase order when an order is resolved.
  • Missing products
    option to automatically create missing products using data from the UBL file. Automated callers can pass purchase_ubl_no_new_products in context to leave unmatched lines unmatched instead of silently creating duplicates.
  • Mapping preview
    the interactive flow previews one row per invoice line with the product the matcher found and how it found it (green = supplier code or barcode, yellow = name only, red = no match); any row can be reassigned to a different product before confirming.
  • Unattended runs surface themselves
    a headless import whose total does not add up, or that leaves lines unmatched, posts a color-coded log and schedules a "SPV import needs review" to-do activity on the purchase order, assigned to its buyer.

The module supports standard UBL Invoice namespaces and common unit code mappings (C62, KGM, LTR, etc.).

Versions

20.0.1.5.1 (2026-11-20)

  • A price declared per 100 or 1,000 units (BaseQuantity) is no longer taken as the price of one unit on the order line and in the vendor prices (fix in deltatech_account_ubl_import), unless the line total shows that the program filled BaseQuantity wrongly (e.g. with the line quantity): then the price is kept and a warning is logged. Fixes #3590.
  • Importing a partial invoice on an order already invoiced in part no longer overwrites the ordered quantity with the quantity of the invoice: the ordered quantity is never lowered below the quantity already invoiced plus the quantity of the document (a line already fully invoiced is left as it is), and importing the same invoice again does not change it. The vendor bill takes the quantity of the document for products billed on ordered quantities; for products billed on received quantities a warning reports the difference. Fixes #3591.

20.0.1.5.0 (2026-11-20)

  • The UBL reader and the product matcher moved to the new base module deltatech_account_ubl_import, installed automatically as a dependency. They are now shared with the vendor bill review (deltatech_vendor_bill_ubl_review). The import works as before; purchase.invoice.import.mixin keeps its name, so the modules that extend it are unchanged.

20.0.1.4.22 (2026-11-02)

  • Fixed: importing an invoice with Update vendor prices checked no longer resets the lead time (delay) of the existing vendor line to 1 day; only the price (converted to the line unit), currency and code are updated.
  • Docs: the consultant sheet states that the lead time of the vendor line is kept on price update. The sheet is also completed: 9 screenshots in readme/screenshots/ (generated by an extended tests/test_screenshots.py), the vendor bill journal items, and corrected accounting notes (with invoice-time valuation the receipt posts no entry).

20.0.1.4.15 (2026-10-22)

  • Listed on Odoo Apps as Purchase UBL Import (was Purchase UBL). The technical name deltatech_purchase_ubl does not change.

20.0.1.4.14 (2026-10-20)

  • Changed: in the import preview, each line now has an action: Use product, Create new product or Ignore. A line without a product is ignored by default; a new product is created only when the user chooses Create new product on that line. The global "Create missing products" option is no longer shown in the wizard (it still applies to the automatic import).
  • The preview also shows the Update vendor prices, Create vendor bill and Validate receipt options, and the result step has an Open Purchase Order button.
  • New preview or import entry point (action_preview_or_import): when every line is matched by vendor code or barcode and, after the import, the order total equals the invoice total, the invoice is imported straight away and the user only gets a notification (the import log is posted on the order). Otherwise the import is rolled back and the preview opens.
  • New context key purchase_ubl_skip_auto_import: a caller that opens the import wizard itself attaches the XML to the order without the automatic import.
  • Port of 19.0.1.4.14 (dhongu/deltatech#3700). Adapted to 20.0: the XML is read from data_file.content (raw bytes) instead of being base64-decoded.

20.0.1.4.13 (2026-10-19)

  • Changed: the automatic import of an XML attached to a purchase order no longer creates the vendor bill when a line of the invoice could not be matched to a product. That bill missed the unmatched lines, and resolving them later on the order did not update it. The import log says why the bill was skipped; create it once every line is resolved.
  • Fixed: an invoice line without a vendor code erased the code already saved on the vendor price row of the product.
  • New extension point for the lines the automatic import could not match, used by Purchase UBL AI Product Matching.
  • Port of 19.0.1.4.13 (dhongu/deltatech#3688).

20.0.1.4.12 (2026-10-16)

  • Fixed: the check for an existing vendor bill with the same supplier invoice number looked at every company the user had access to. It now looks only in the company of the purchase order.
  • Fixed: updating the vendor price of a product variant could overwrite the vendor price row of another variant of the same product, or a row of another company. Only the row of the imported variant in the order's company (or a row shared between companies) is updated now; a new row is created otherwise.
  • Fixed: the unit code SET was mapped to a unit that does not exist in Odoo and was handled as Units. A unit named "Set" is used when one is defined. A unit code that is not recognised is now reported in the import log.
  • Port of 19.0.1.4.12 (dhongu/deltatech#3561).

20.0.1.4.11 (2026-10-12)

  • Fixed: the vendor was not found by its tax id when the invoice and the partner wrote the Romanian CUI differently (with or without the RO prefix, with spaces); only an exact name match was left. The tax ids are now compared without spaces and without the RO prefix (other countries keep theirs), which also removes the false "Supplier VAT ... differs" warning. For a supplier not registered for VAT, the CUI is read from PartyLegalEntity/CompanyID.

20.0.1.4.10 (2026-10-12)

  • Fixed: a supplier credit note (a CreditNote document, or an Invoice with type code 381) was imported as an invoice. A CreditNote created a vendor bill from the order instead of a refund; an Invoice 381 wrote negative quantities on the order lines and overwrote the vendor prices. Credit notes are now recognised and not imported: the order is left as it is, the log shows a warning and the automatic import schedules the "SPV import needs review" activity. Record the vendor refund manually.

20.0.1.4.9 (2026-10-12)

  • Fixed: a supplier invoice imported on a purchase order with nothing left to invoice (already fully invoiced, or billed on received quantities with nothing received yet) created a vendor bill with every line at zero quantity. The bill is now skipped with a message in the log, and the automatic import schedules the "SPV import needs review" activity on the order, since it may be a duplicate invoice or an extra charge.
