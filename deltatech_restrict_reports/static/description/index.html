Overview

Restricts who can see the data of the Sales Analysis (Sales > Reporting) and Invoice Analysis (Accounting/Invoicing > Reporting) reports, independently of any other access a user already has (Salesperson, Invoicing, Accounting...).

Two new groups control visibility:

  • Rapoarte Vânzări/Facturi: doar propriile înregistrări - sees only his own records (Salesperson on the order / invoice).
  • Rapoarte Vânzări/Facturi: toate înregistrările - sees every record.

A user assigned to neither group sees these two reports empty (no access error). Nobody is granted either group automatically - assignment is manual, from Settings > Users.

Usage

Give each user a report access level

Go to Settings → Users & Companies → Users, open the user and, on the Access Rights tab, find the Restrict Reports section. In its Restrict Reports field choose:

  • Rapoarte Vânzări/Facturi: doar propriile înregistrări (own records only);
  • Rapoarte Vânzări/Facturi: toate înregistrările (all records);
  • leave it empty for no data at all.

Right after installation nobody has either group, so everybody, administrators included, sees the two reports empty until the groups are assigned.

1 User form, Access Rights tab: Sales is Administrator, Accounting is Invoicing, and in the Restrict Reports section the field is set to own records only

Sales Analysis

Open Sales → Reporting → Sales, switch to the Pivot view and group by Salesperson.

  • With own records only, the pivot has a single row, the logged-in user, equal to the total.
2 Sales Analysis pivot grouped by Salesperson for Marc Demo: a single row, Marc Demo, 54 Qty Ordered in total
  • With all records, every salesperson appears, with the same figures for each of them.
3 Sales Analysis pivot grouped by Salesperson for a user with all records: Marc Demo 54 and Mitchell Admin 94, total 148 Qty Ordered

Invoice Analysis

Open Invoicing → Reporting → Management → Invoice Analysis and group by Salesperson. With own records only, only the invoices where the user is the salesperson are counted; invoices of other salespersons or without a salesperson are left out.

4 Invoices Analysis pivot grouped by Salesperson for Marc Demo: a single row, Marc Demo, 84,750.00 Untaxed Amount

With all records, the other salespersons and the invoices without a salesperson (None) appear too; the user's own row keeps the same amount.

5 Invoices Analysis pivot grouped by Salesperson for a user with all records: Marc Demo 84,750.00, Mitchell Admin 1,275.00 and None 44,299.00, total 130,324.00

User without a group

A user in neither group still sees the menus, but both reports open empty, without an access error.

6 Invoices Analysis for a user without any report group: no data, Odoo's faded sample chart in the background and its help text for an empty report

Notes

  • The Sales → Reporting menu requires the Sales: Administrator right in standard Odoo; the module does not change menu access.
  • These two analysis reports, and the Sold button on products (computed from Sales Analysis), are filtered; orders, invoices, the Invoiced button on customers and accounting reports are not.
Versions

20.0.1.0.0 (2026-11-17)

  • Migrated to 20.0, still data-only (empty __init__.py, installs on Odoo Online through Apps > Import Module).
  • The two global ir.rule records became global ir.access restrictions (security/ir.access.csv, no group, operation r). Restrictions are AND-ed with the group permissions of sale / account, so the own / all / none tiers behave as on 19.0. The xml ids sale_report_restrict_rule and account_invoice_report_restrict_rule are kept.
  • A user in neither group still gets zero rows, not an AccessError: the "no access" branch is now [('id', '=', 0)], because on 20.0 a statically false domain such as [(0, '=', 1)] makes the whole model inaccessible and search() raises.
  • Tests for the three tiers on Sales Analysis and Invoice Analysis.
  • Consultant sheet, USAGE.md and screenshots from 19.0 (#4221), redone on Odoo 20. On 20.0 the Invoiced button on customers is computed from the invoices, so it is no longer filtered; only Sold on products is.

  • Apps Store banner: the "Odoo Online" badge shows that the module has no Python code and installs on Odoo Online.
