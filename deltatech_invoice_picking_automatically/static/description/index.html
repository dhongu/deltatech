Overview

Invoices the validated transfers automatically, each transfer on its own document and with the quantities it moved:

  • delivery → customer invoice, posted when Post Invoice Automatically is set;
  • customer return → customer credit note;
  • receipt → vendor bill, always left in draft (it is posted when the vendor's document arrives);
  • return to vendor → vendor refund, in draft.

Features:

  • Configuration on the operation type: Create Invoice Automatically, Invoice Moment and Post Invoice Automatically.
  • Invoice Moment
    Scheduled (the daily scheduled action invoices the queued transfers, the default) or On validation (the transfer is invoiced right after it is validated).
  • Backorders and partial deliveries are invoiced separately, with the quantities of each transfer. A transfer that is already invoiced is not invoiced again.
  • Only transfers that come from a sale or a purchase order are queued.
  • The invoicing runs with system rights, so a warehouse user without invoicing rights can validate transfers of an operation type that invoices on validation.
  • Error handling: each transfer is invoiced in its own savepoint. If the invoicing fails, the transfer stays done, is marked Failed and keeps the reason, shown on the transfer. The Retry Invoicing button invoices it again after the cause is fixed.
  • The Automatic Invoicing status on the transfer form and as an optional column in the list, and the Automatic Invoicing Failed and To Invoice Automatically filters.
Usage

Configure the operation type

  1. Go to Inventory → Configuration → Operation Types and open the operation type (for example Delivery Orders). Check Create Invoice Automatically, choose the Invoice Moment and, for customer invoices, Post Invoice Automatically.
1 Delivery Orders operation type with Create Invoice Automatically, Invoice Moment On validation and Post Invoice Automatically

Invoice on validation

  1. Validate a delivery of a sale order. The invoice is created right away, with the delivered quantities. The transfer shows Automatic Invoicing = Invoiced, and the Additional Info tab links the invoice. A return uses the return operation type (for deliveries, usually Receipts), so the moment and the posting of the credit note are the ones set there.
2 Validated delivery of order S00101 with Automatic Invoicing Invoiced and the linked invoice
  1. With Post Invoice Automatically, the customer invoice is posted.
3 Posted customer invoice with the delivered quantity, 6 Scaun ergonomic Nova

Scheduled invoicing

  1. On an operation type with Invoice Moment = Scheduled, the validated transfers wait as To Invoice and are invoiced by the daily scheduled action Generate Invoices from Pickings. A receipt gets a vendor bill in draft, with the received quantities.
4 Draft vendor bill created for the receipt of order P00101, 5 Birou reglabil Flex

When the invoicing fails

  1. The transfer stays done and is marked Failed. The reason is shown at the top of the form. Fix the cause, then click Retry Invoicing. Here the receipt was billed by hand from the purchase order before the scheduled action, so there is nothing left to bill: in the Additional Info tab, select the existing bill in Invoice, clear To invoice, then click Retry Invoicing.
5 Receipt with Automatic Invoicing Failed, the reason The selected receipts are already billed and the Retry Invoicing button
  1. In Inventory → Operations → Transfers → Receipts (or Deliveries), add the Automatic Invoicing Failed filter. Remove the Receipts filter to see the failed transfers of all types. The Automatic Invoicing column can be shown from the optional columns menu.
6 Receipts list with the Receipts and Automatic Invoicing Failed filters and the Automatic Invoicing column
Versions

20.0.1.0.0 (2026-11-21)

  • Migration to Odoo 20.0. Tests: customer return through picking._create_return() (the stock.return.picking wizard is gone), no write on the computed is_company.

19.0.1.0.0 (2026-11-18)

  • Each transfer gets its own document, with its own quantities: a delivery gets a customer invoice, a customer return a credit note, a receipt a draft vendor bill and a return to vendor a draft refund. Backorders are invoiced separately. Depends on deltatech_invoice_picking (dhongu/deltatech#4033).
  • Only transfers with a sale or purchase order are queued. A queued transfer without an order fails with a reason instead of staying in the queue (dhongu/deltatech#3583).
  • New Invoice Moment on the operation type: Scheduled (default, as before) or On validation. The invoicing runs with system rights, so warehouse users need no invoicing rights. A failure keeps the reason on the transfer, shown on the form, with a Retry Invoicing button, an optional list column and the Automatic Invoicing Failed / To Invoice Automatically filters (dhongu/deltatech#4035).

19.0.0.0.7 (2026-10-22)

  • Listed on Odoo Apps as Auto-Invoice from Delivery (was Invoice Pickings Automatically). The technical name deltatech_invoice_picking_automatically does not change.

19.0.0.0.6 (2026-10-09)

  • Each automatic invoicing in the cron now runs in its own savepoint. An error (posting validation or database error) rolls back only that picking's work, so no orphan draft invoice is left behind, the picking is marked as failed and logged, and the other pickings of the run are still invoiced.

19.0.0.0.5 (2026-09-29)

  • Own module icon, instead of the generic gears it had.
