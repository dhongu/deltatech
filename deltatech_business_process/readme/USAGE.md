1. **Design**: create a **Project** (Business Process app), define **Business Areas** and, optionally, **Process Groups** to classify work. Add **Business Processes** to the project and break each one into ordered **Steps**, assigning a responsible party and, if relevant, a related business transaction.
2. **Testing**: from a process, start a test of the required scope (**Internal**, **Integration** or **User Acceptance**). The module auto-generates a test record with one step-test per process step.
3. Execute the test: record the date, mark each step-test result (**Passed**/**Failed**) and add observations. Raise a **Business Issue** directly from a failing step-test; issues flow through **Draft → Open/Allocated → Solved/In Test → Closed** (or **Reopened**). Closing the last open issue on a step-test can automatically mark it as passed.
4. **Go-live**: once all required tests are complete, move the process to **Ready** and then **Production**.
5. **Developments**: link required customizations as **Business Development** records to the relevant processes/projects to track scope and duration.
6. **Export/Import**: from the Business Processes list, use **Export** to save one or more processes as JSON (optionally including tests, responsible, customer and support info); use **Import** on a Project to bootstrap it from a previously exported JSON. Keep Responsible/Customer Responsible/Support names consistent across databases to avoid duplicate contacts being created on import.
7. **Reports**: print the **Business Process** or **Business Process Test** report from the relevant record; generate an **Excel summary** from a Project to see durations grouped by Business Area, highlighting processes with zero total duration.
8. Use the **Attachments** smart button on Projects/Processes to see all documents related to the record and its tests in one place.
