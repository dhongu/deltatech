## 19.0.1.1.1 (2026-11-16)

- Empty `__init__.py` restored: the OCA tools (manifestoo, oca-checks-odoo-module) do not
  recognize a module without it, so the CI of the suites that depend on this module failed.
  The module still has no Python code and still imports on Odoo Online.
- Explicit Odoo Online marker: `"online": true` in `static/description/banner.json`
  (the banner no longer infers it from the missing `.py` files).

## 19.0.1.1.0 (2026-11-16)

- Data-only module, importable on Odoo Online (Custom plan) from **Apps > Import Module**: the
  `__init__.py` files and the `tests/` folder were removed, because Odoo Apps treats any `.py`
  file as Python code and does not list the module as available on Odoo Online.
- The Python runner of the JavaScript tests (`tests/test_js.py`) and the screenshot test of the
  consultant sheet (`tests/test_screenshots.py`) were removed; the Hoot tests stay in
  `static/tests/` and run with the web unit tests
  (`/web/tests?filter=@deltatech_widget_many2one_badge`).

# Changelog

## 19.0.1.0.2 (2026-09-28)

- Fix: the Hoot unit tests never ran. Hoot only executes modules whose name
  ends in `.test`, so `many2one_badge_field.test.esm.js` was loaded but
  silently skipped ("Passed 0 tests"). Renamed it to
  `many2one_badge_field.test.js`.
- Added `tests/test_js.py`, so the Hoot tests run with the Python test suite
  (and in CI).
- The edit mode test now checks removing the value, picking another partner
  from the autocomplete and saving; a new test checks that clicking the badge
  opens the color picker and writes the chosen color on the partner.
  The edit mode test is desktop only: on mobile the autocomplete opens a
  dialog instead of a dropdown.
